# クイズ回答・自動集計プロトタイプ（クラウド版）使い方

トンネル方式・LAN方式の代替です。
サーバーは学校のタブレットではなく、インターネット上のクラウドで動きます。
問題はテスト用の超簡単な算数10問、チームは1〜20です。本番の問題は未決定です。

## なぜ学校で通りやすいか（切り分け）
- 管理者権限：不要。タブレットに何もインストールしない。
- ファイアウォール：当たらない。学校側で問題になるのは「外から親機へ入る接続」で、
  この方式では全端末が「外のサーバーへ出ていく接続（HTTPS）」だけをする。
- exeのダウンロード・実行：なし。
- Python：タブレット側には不要。Pythonはクラウド側で動く。
- 同じWi-Fi：不要。全端末がインターネットにつながっていればよい。

## 残る可能性（未検証）
- 学校のプロキシが、デプロイ先ドメインへの接続自体を止める場合だけ失敗する。
  これは現地で1回、発行URLを開いてみないと分からない。
- 無料枠は一定時間アクセスが無いとサーバーが眠り、最初の表示に30〜60秒かかる場合がある。
  テスト開始の少し前に親機で一度開いて起こしておく。

## 置き方（1回だけ、ブラウザで完結する手順・Renderの例）
1. このフォルダ一式を GitHub のリポジトリに置く
   （server.py / Procfile / render.yaml が入っていればOK）
2. render.com にサインアップし、New → Web Service でそのリポジトリを選ぶ
3. render.yaml を読み取るので設定は自動で入る。Start Command が
   `python server.py` になっていることだけ確認して Deploy
4. 発行されたURL（例：https://quiz-prototype.onrender.com）が公開先になる
   - 子機（回答）：そのURLを開く
   - 親機（司会・集計）：そのURLの後ろに /host を付けて開く

※ 置き先はRender以外（Railwayなど、Pythonを動かせる所）でもよい。
   ポートは環境変数 PORT に自動対応済み。

## 試し方（3台テスト）
1. 子機2台で発行URLを開き、それぞれ違うチーム番号を選ぶ（例：1と2）
2. 親機で /host を開き「問題を開始」
3. 子機に問題が出るので A〜D で回答（1問1回・変更不可）
4. 親機で「回答済み ○チーム」が増えるのを確認
5. 親機で「回答を締め切る」→「正解発表（自動採点）」
6. 子機に正解・不正解が出て、親機の順位表が更新される
7. 「次の問題へ」で進行。全10問で終了。「リセット」で最初に戻る

## 注意
- 公開URLを知っている人は誰でも参加できるため、テスト用としてのみ使う。
- サーバーを止めると集計は消える（このプロトタイプは保存機能なし）。
